# Rasbhav Books V3.0 — project instructions

## Source of truth
- Follow `docs/architecture/MASTER-ARCHITECTURE.md` and `docs/architecture/ENTERPRISE-SECURITY-ARCHITECTURE.md`.
- Follow their phased roadmap. Build only the current phase; leave later features documented until their phase.
- The old Flask project is reference-only. Never modify its repository.
- Make all V3.0 changes in this repository and preserve meaningful Git history.

## Work with the project owner
- The owner prefers Gujarati and is learning MERN. Explain each step in simple Gujarati before asking them to run it.
- Keep changes small, modular, and beginner-friendly. Do not require coding from the owner.
- Ask a concise question when a requirement is unclear or a decision affects money, legal terms, security, or irreversible product behavior.
- Prefer low-cost tools and avoid introducing paid services without discussion.

## Engineering rules
- Mobile-first, accessible UI; validate every input on the server.
- Never commit secrets, credentials, real customer data, or unpublished manuscripts.
- Do not claim a feature is complete unless implementation, validation, error states, responsive behavior, relevant tests, and documentation have been checked.
- Keep financial records ledger-based; do not derive history from a mutable balance.
- Do not deploy untested changes.
