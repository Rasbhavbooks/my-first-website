# Current state and next steps

This file records implementation status; the complete requirements remain in the master architecture documents.

## Implemented

- React/Vite frontend with responsive home, book catalogue, multilingual search across localized titles and descriptions, author, category, and book language, category and language filters, and title/author sorting. The homepage and localized category pages use filtered server-side pagination (24 books per request, up to 48) for catalogue search, ISBN, category, language, and sorting, with a browser sample-catalogue fallback if the API is unavailable. ISBN-10/13 values are checksum-validated on author drafts and admin catalogue edits, shown on public book details and Book structured data, and included in catalogue search. INR prices use one locale-aware formatter on public book cards, book details, and admin review. Recent search history is stored in browser-local storage, shown as suggestions, and can be cleared; matching catalogue book title/author suggestions link directly to book details. Optional popular search trends require explicit browser-local opt-in: only terms matching a catalogue book, author, category, or language are counted, counts are not linked to accounts or stored with IP addresses, expire after 90 days, and are shown only after at least three searches. Admins can write localized descriptions for book categories; public, localized category pages show those descriptions and list active-category books, link from the homepage filters, and set client-side canonical/social metadata.
- Gujarati, Hindi, and English interface translations.
- Express/Mongoose API with MongoDB Atlas configuration, health endpoint, book catalogue endpoints, and repeatable sample-book seed command.
- Reader registration, email verification, login, logout, seven-day server-side sessions, profile editing, and password changes. Passwords use Argon2id; sessions use random HttpOnly cookies. Readers can view their active sessions and revoke any one session, including the current device; the interface stores and displays no device fingerprint or IP address.
- Transactional email adapter for Resend using server-only RESEND_API_KEY, a verified EMAIL_FROM, and an explicit public APP_BASE_URL. Verification and password-reset links expire after 30 minutes; tokens are stored as hashes and are single-use.
- Registration and password-reset email links work only when all email configuration is present. Without email configuration, development keeps its manual verification/reset-token flow. Production registration and reset remain disabled until email delivery is configured.
- Readers can request a new verification email without revealing whether an email belongs to a pending account. Login and authentication endpoints are rate-limited.
- Signed-in readers can update display name, bio, up to 10 hobbies, and an HTTPS profile-photo URL. They can also upload a private JPEG, PNG, or WebP profile photo up to 5 MB; the API validates the file signature, requires a clean ClamAV scan, and stores the image in private Cloudflare R2. The authenticated photo endpoint uses no-store and nosniff headers; private object keys are never returned. Password changes and resets revoke existing sessions.
- Signed-in readers can download an account-data JSON export containing their profile, wishlist, author follows, reviews and helpful votes, author application/profile, draft metadata, and private chapter text. Exports exclude passwords, sessions, reset/verification tokens, MFA secrets, browser-only preferences, and uploaded file bytes; the endpoint is authenticated, rate-limited, and sent with no-store headers.
- Guest wishlists are browser-local. Signed-in readers can sync saved catalogue books to an account-owned MongoDB wishlist.
- Public home, book-detail, author-profile, CMS-page, and blog-post routes update localized page titles/descriptions, canonical/Open Graph/Twitter metadata, and relevant WebSite, Book, ProfilePage, CollectionPage, WebPage, or BlogPosting JSON-LD in the client. Search/social crawlers that do not execute the SPA still need server-rendered route metadata; root-level sitemap/robots routing depends on the production host and remains pending.
- Book detail pages show deterministic, rule-based related-book recommendations from the public catalogue. Category, author, and language matches are scored; no reader history or private author drafts are used. The API endpoint is `GET /api/v1/books/:bookId/related`, and the client falls back to the bundled sample catalogue when the API is unavailable in development.
- Readers can write one 1–5 star review per catalogue book, edit/delete their own review, mark other visible reviews helpful once per account (and undo that vote), report reviews, and follow/unfollow catalogue authors. Helpful votes require a signed-in reader, are stored with a unique review/account constraint, and never expose voter identities. Public review summaries omit reader email and credentials.
- Admin-only review moderation routes and page can list reports, resolve them, and hide/restore reviews.
- The MFA-protected admin dashboard shows aggregate account/workflow counts and safe setup readiness for database, email, MFA, R2, and ClamAV configuration. Readiness does not reveal secret values. It checks the configured ClamAV daemon with a bounded PING request. An admin can manually request a bounded, read-only Cloudflare R2 `HeadBucket` check; that request is not made automatically. Email delivery is not probed.
- The admin dashboard shows aggregate counts for active accounts, readers, authors, catalogue books, pending author applications, pending book reviews, and pending review reports. These counts are available only to authenticated admins with MFA enabled.
- MFA-enabled administrators can review paginated, read-only history of successful admin write actions. Events retain the internal admin ID, HTTP method, sanitized route template, success status, and timestamp; request bodies, query values, and IP addresses are excluded. The history API is admin-only and returns no-store responses.
- Administrator accounts enroll in TOTP MFA after password login. TOTP secrets are encrypted with a server-only 32-byte key; recovery codes are hashed and consumed once. All admin API and page routes require an enabled MFA record. The MFA-protected security page lists up to 50 recent sessions for active administrator accounts and marks the current session; it shows internal admin ID and display name, without collecting device fingerprints or IP addresses.
- Admins can search and filter user accounts by name, email, role, and status. The user list exposes only basic account fields; admins can suspend or restore verified reader/author accounts, and suspension revokes all of that user's active sessions. Admin accounts, the current admin, and unverified accounts cannot be changed from this page.
- Admins can search author storefronts and view follower, public-catalogue, draft, and submitted-book totals. They can suspend/restore author profiles; suspension hides the public storefront and blocks author-only API routes while preserving the account. A suspended user account must be restored before its author profile can be restored.
- Admins can search existing public catalogue entries and edit localized titles and descriptions, language, category, price, badge, and card theme. The original catalogue author credit and book ID remain fixed. This does not publish author drafts or enable purchases.
- Admins can select up to four existing public-catalogue books for a homepage featured-books widget; this does not publish author drafts or enable sales. Admins can configure maintenance mode, which serves a localized notice to public visitors and returns 503 for public API actions while keeping protected admin routes available; the mode is off by default. Admins can choose the default language for new visitors (saved visitor preferences take priority), manage localized homepage search titles and descriptions, edit the localized homepage hero, reorder and show or hide built-in sections (book discovery stays visible), add up to four localized custom text sections with optional same-site links and published media-library images, manage localized header links, footer copy, browse links, and the community column title and links, and turn an optional announcement banner on or off. Site links are restricted to same-site paths or page anchors.
- Admins can add and localize categories in Gujarati, Hindi, and English, change display order, and disable unused categories. Categories with catalogue books or author drafts cannot be disabled. Reader filters, author drafts, and catalogue editing use the active database categories.
- Admins can upload scanned JPEG/PNG/WebP images to private Cloudflare R2 storage, add alt text in all three languages, publish/unpublish them, and copy same-site image URLs for the homepage CMS. Only published images are served publicly.
- Admins can create, edit, and publish/unpublish static CMS pages and blog articles with Gujarati, Hindi, and English text. Blog drafts stay private; publication requires all three translations and readers see only published posts. Pages and blog posts support localized SEO titles/descriptions. Draft pages remain private; public pages are linked in the footer. Published `privacy`/`privacy-policy` and `terms`/`terms-of-service` pages also appear as localized legal links; those links stay hidden until the matching CMS pages are published. Publishing requires complete titles and body text in all three languages.
- Signed-in readers can submit a writer application with biography, writing languages, genres, and an optional HTTPS sample link. Applications are rate-limited; pending applications cannot be duplicated, and rejected applications can be resubmitted.
- Admins can view and approve/reject author applications. Approval uses a database transaction to create a public author profile and promote the reader to the author role. Author profile writes require the author role and are rate-limited.
- Approved authors can update their public biography, HTTPS website link, profile photo URL, and storefront cover image URL. They can feature up to three books from their existing public catalogue. Public author pages show approved profiles, profile branding, catalogue books under the author's original catalogue credit, and follower counts. The Author Studio shows aggregate follower totals, new followers over the last 7 and 30 days, catalogue-book totals, and author-owned draft/review-status totals without exposing reader identities. Readers can follow active author profiles and open followed authors from their account.
- Authors can create and edit book drafts and submit completed metadata for administrator review. Admins can approve or request changes with a note. Author-owned routes enforce author role and ownership; admin review routes require admin access.
- Author book drafts accept JPEG/PNG/WebP covers and PDF manuscripts. Admins can configure whole-megabyte limits for new cover uploads from 1–10 MB (default 5 MB) and manuscripts from 1–25 MB (default 25 MB); server and author UI enforce the saved limits, while the upload parser retains a 25 MB hard ceiling. The API checks MIME type and file signatures, requires a successful ClamAV scan, then stores files in a private Cloudflare R2 bucket. MongoDB stores metadata and private object keys; API responses never expose keys or public object URLs.
- Authors can retrieve only their own book files; admins can retrieve files for submitted or approved books. Upload endpoints are rate-limited, filenames are sanitized, and downloads are sent as attachments with no-store and nosniff headers.
- Authors can create, edit, and delete up to 100 plain-text chapters per draft, with a 100,000-character limit per chapter. Chapter records are separate from book documents, private to the owning author, and visible to admins only while the book is under review. Public chapter reading is not enabled.
- File upload stays unavailable until R2 credentials are configured and ClamAV is reachable. The Codespaces devcontainer starts ClamAV privately on its internal Docker network; existing Codespaces need one rebuild after this configuration is merged. Local development outside Codespaces and production still require a separately configured private ClamAV daemon. Admin approval currently records a review decision only; it does not publish to the public catalogue or enable sales/read access.
- A one-time CLI bootstrap can promote an existing active, email-verified reader to the first admin. It requires a typed confirmation, runs only when no admin exists, and is not exposed through the web API.
- GitHub Actions runs the repository's quality checks on pushes and pull requests, including the frontend build, workspace tests, development-launcher syntax, and Codespaces Docker Compose validation.

## Not implemented

Broader platform settings, server-rendered SEO metadata and root-level sitemap/robots routing, book publication to the public catalogue, account deletion, passkeys/WebAuthn and hardware keys, verified-purchase review labels, production email deliverability monitoring, paid reader access and reading, purchases/payments, subscriptions, royalty ledger, broader CMS features, affiliates, institutions, audiobooks, AI tools, and mobile apps.

## Phase 7 launch decisions

- The owner selected digital eBooks only for the initial sales format; print-on-demand is outside the first-release scope.
- Checkout and paid access stay disabled until the payment gateway, one-time purchase versus membership model, prices, platform/author revenue split, tax and refund policies, and author-rights wording are approved. No payment provider or financial terms are assumed.

## Next phase

Continue Phase 7: Commerce & Membership. Book prices are already stored in catalogue entries and author drafts, but orders, payments, refunds, subscriptions, coupons, and invoices are not implemented. The initial format is digital eBooks only. Keep checkout and paid access disabled until the remaining payment and financial terms listed above are approved; keep public publishing of author drafts disabled until the author-rights wording is approved. Phase 5 file uploads remain unavailable until a private Cloudflare R2 bucket and reachable ClamAV daemon are configured. Configure `ADMIN_MFA_ENCRYPTION_KEY` before administrator access, and configure email secrets plus the public frontend URL before enabling production registration or password reset. Follow the phases and Definition of Done in the master architecture.
