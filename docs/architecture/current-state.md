# Current state and next steps

This file records implementation status; the complete requirements remain in the master architecture documents.

## Implemented

- React/Vite frontend with responsive home, book catalogue, multilingual search across localized titles and descriptions, author, category, and book language, category and language filters, and title/author sorting. Search, filters, and sorting work across the sample catalogue in the browser; search history, trend analytics, ISBN lookup, and large-catalogue server pagination remain pending. Admins can write localized descriptions for book categories; public, localized category pages show those descriptions and list active-category books, link from the homepage filters, and set client-side canonical/social metadata.
- Gujarati, Hindi, and English interface translations.
- Express/Mongoose API with MongoDB Atlas configuration, health endpoint, book catalogue endpoints, and repeatable sample-book seed command.
- Reader registration, email verification, login, logout, seven-day server-side sessions, profile editing, and password changes. Passwords use Argon2id; sessions use random HttpOnly cookies.
- Transactional email adapter for Resend using server-only RESEND_API_KEY, a verified EMAIL_FROM, and an explicit public APP_BASE_URL. Verification and password-reset links expire after 30 minutes; tokens are stored as hashes and are single-use.
- Registration and password-reset email links work only when all email configuration is present. Without email configuration, development keeps its manual verification/reset-token flow. Production registration and reset remain disabled until email delivery is configured.
- Readers can request a new verification email without revealing whether an email belongs to a pending account. Login and authentication endpoints are rate-limited.
- Signed-in readers can update display name, bio, up to 10 hobbies, and an HTTPS profile-photo URL. Photo upload/storage is not configured. Password changes and resets revoke existing sessions.
- Signed-in readers can download an account-data JSON export containing their profile, wishlist, author follows, reviews and helpful votes, author application/profile, draft metadata, and private chapter text. Exports exclude passwords, sessions, reset/verification tokens, MFA secrets, browser-only preferences, and uploaded file bytes; the endpoint is authenticated, rate-limited, and sent with no-store headers.
- Guest wishlists are browser-local. Signed-in readers can sync saved catalogue books to an account-owned MongoDB wishlist.
- Public home, book-detail, author-profile, CMS-page, and blog-post routes update localized page titles/descriptions, canonical/Open Graph/Twitter metadata, and relevant WebSite, Book, ProfilePage, CollectionPage, WebPage, or BlogPosting JSON-LD in the client. Search/social crawlers that do not execute the SPA still need server-rendered route metadata; root-level sitemap/robots routing depends on the production host and remains pending.
- Readers can write one 1–5 star review per catalogue book, edit/delete their own review, mark other visible reviews helpful once per account (and undo that vote), report reviews, and follow/unfollow catalogue authors. Helpful votes require a signed-in reader, are stored with a unique review/account constraint, and never expose voter identities. Public review summaries omit reader email and credentials.
- Admin-only review moderation routes and page can list reports, resolve them, and hide/restore reviews.
- The MFA-protected admin dashboard shows aggregate account/workflow counts and safe setup readiness for database, email, MFA, R2, and ClamAV configuration. Readiness does not reveal secret values and does not claim to probe R2, email delivery, or ClamAV reachability.
- The admin dashboard shows aggregate counts for active accounts, readers, authors, catalogue books, pending author applications, pending book reviews, and pending review reports. These counts are available only to authenticated admins with MFA enabled.
- Administrator accounts enroll in TOTP MFA after password login. TOTP secrets are encrypted with a server-only 32-byte key; recovery codes are hashed and consumed once. All admin API and page routes require an enabled MFA record.
- Admins can search and filter user accounts by name, email, role, and status. The user list exposes only basic account fields; admins can suspend or restore verified reader/author accounts, and suspension revokes all of that user's active sessions. Admin accounts, the current admin, and unverified accounts cannot be changed from this page.
- Admins can search author storefronts and view follower, public-catalogue, draft, and submitted-book totals. They can suspend/restore author profiles; suspension hides the public storefront and blocks author-only API routes while preserving the account. A suspended user account must be restored before its author profile can be restored.
- Admins can search existing public catalogue entries and edit localized titles and descriptions, language, category, price, badge, and card theme. The original catalogue author credit and book ID remain fixed. This does not publish author drafts or enable purchases.
- Admins can select up to four existing public-catalogue books for a homepage featured-books widget; this does not publish author drafts or enable sales. Admins can configure maintenance mode, which serves a localized notice to public visitors and returns 503 for public API actions while keeping protected admin routes available; the mode is off by default. Admins can choose the default language for new visitors (saved visitor preferences take priority), manage localized homepage search titles and descriptions, edit the localized homepage hero, reorder and show or hide built-in sections (book discovery stays visible), add up to four localized custom text sections with optional same-site links and published media-library images, manage localized header links, footer copy, browse links, and the community column title and links, and turn an optional announcement banner on or off. Site links are restricted to same-site paths or page anchors.
- Admins can add and localize categories in Gujarati, Hindi, and English, change display order, and disable unused categories. Categories with catalogue books or author drafts cannot be disabled. Reader filters, author drafts, and catalogue editing use the active database categories.
- Admins can upload scanned JPEG/PNG/WebP images to private Cloudflare R2 storage, add alt text in all three languages, publish/unpublish them, and copy same-site image URLs for the homepage CMS. Only published images are served publicly.
- Admins can create, edit, and publish/unpublish static CMS pages and blog articles with Gujarati, Hindi, and English text. Blog drafts stay private; publication requires all three translations and readers see only published posts. Pages and blog posts support localized SEO titles/descriptions. Draft pages remain private; public pages are linked in the footer. Publishing requires complete titles and body text in all three languages.
- Signed-in readers can submit a writer application with biography, writing languages, genres, and an optional HTTPS sample link. Applications are rate-limited; pending applications cannot be duplicated, and rejected applications can be resubmitted.
- Admins can view and approve/reject author applications. Approval uses a database transaction to create a public author profile and promote the reader to the author role. Author profile writes require the author role and are rate-limited.
- Approved authors can update their public biography, HTTPS website link, profile photo URL, and storefront cover image URL. They can feature up to three books from their existing public catalogue. Public author pages show approved profiles, profile branding, catalogue books under the author's original catalogue credit, and follower counts. The Author Studio shows aggregate follower totals, new followers over the last 7 and 30 days, catalogue-book totals, and author-owned draft/review-status totals without exposing reader identities. Readers can follow active author profiles and open followed authors from their account.
- Authors can create and edit book drafts and submit completed metadata for administrator review. Admins can approve or request changes with a note. Author-owned routes enforce author role and ownership; admin review routes require admin access.
- Author book drafts accept JPEG/PNG/WebP covers up to 5 MB and PDF manuscripts up to 25 MB. The API checks MIME type and file signatures, requires a successful ClamAV scan, then stores files in a private Cloudflare R2 bucket. MongoDB stores metadata and private object keys; API responses never expose keys or public object URLs.
- Authors can retrieve only their own book files; admins can retrieve files for submitted or approved books. Upload endpoints are rate-limited, filenames are sanitized, and downloads are sent as attachments with no-store and nosniff headers.
- Authors can create, edit, and delete up to 100 plain-text chapters per draft, with a 100,000-character limit per chapter. Chapter records are separate from book documents, private to the owning author, and visible to admins only while the book is under review. Public chapter reading is not enabled.
- File upload stays unavailable until R2 credentials and a reachable ClamAV daemon are configured. Admin approval currently records a review decision only; it does not publish to the public catalogue or enable sales/read access.
- A one-time CLI bootstrap can promote an existing active, email-verified reader to the first admin. It requires a typed confirmation, runs only when no admin exists, and is not exposed through the web API.
- GitHub Actions runs the repository's existing quality checks on pushes.

## Not implemented

Broader platform settings, server-rendered SEO metadata and root-level sitemap/robots routing, book publication to the public catalogue, account deletion, passkeys/WebAuthn and hardware keys, verified-purchase review labels, helpful-review voting, production email deliverability monitoring, paid reader access and reading, purchases/payments, subscriptions, royalty ledger, broader CMS features, affiliates, institutions, audiobooks, AI tools, and mobile apps.
